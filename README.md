# logmask — маскирование чувствительных данных в логах

Перед тем как отправить лог в тикет, чат, подрядчику или в LLM, прогоните его через logmask.
Нужен только Python 3.11+, ничего устанавливать не требуется.

## Как пользоваться

**Без консоли:** перетащите лог-файл (или несколько, или папку) мышкой на `перетащи_сюда_лог.bat`.
Рядом появится `имя.masked.log`. Исходный файл не меняется никогда.

**Из консоли:**

```
logmask service.log                    → service.masked.log рядом
logmask service.log -o safe.log
logmask .\logs\ -o .\logs_masked\      → вся папка, включая .gz, структура сохраняется
type app.log | logmask - > safe.log    → через pipe
logmask --check service.log            → ничего не пишет, показывает, что нашлось
```

После работы выводится сводка — проверьте её взглядом:

```
✔ service.masked.log — 12408 строк — EMAIL: 37   PHONE: 22   CARD: 14   SECRET: 5
```

Если в платёжном логе `CARD: 0`, а вы знаете, что карты там есть, — сообщите, нужно правило.

Если в сводке есть `⚠ нераспознанных длинных чисел: N` — запустите `logmask --check файл.log`
и посмотрите строки со знаком `?`. Это числа из 10–20 цифр, которые не подошли ни под одно правило
(в отчёте они показаны частично: `«?770**********01»`). Если это данные клиента —
добавьте поле в `rules.toml` или запустите с `--strict`, тогда такие числа станут `[NUM_1]`.

## Что маскируется

| Что | Как выглядит в результате |
|---|---|
| Пароли, токены, ключи по имени поля (`password=`, `"token":`, `apiKey:`, `<pwd>`, `passwordHash`) | `password=[SECRET_1]` |
| `Authorization: Basic/Bearer ...`, Cookie, JWT, ключи `sk-…`, `ghp_…`, `AKIA…` | `Bearer [TOKEN_1]` |
| Логин:пароль в URL | `jdbc:postgresql://app:[SECRET_2]@db` |
| Номера карт, включая Uzcard/Humo: префикс платёжной системы + проверка Луна | `[CARD_1 *1111]` |
| CVV, срок действия | `[CARD_DATA_1]` |
| Email | `[EMAIL_1]` |
| Телефон: с `+`; с кодом 998 даже без `+` (`998901234567`); `8 (916) 123-45-67`; по полю (`phone`, `OpLogin`, `customerPhone`) | `[PHONE_1]` |
| Логин по имени поля (`login`, `userLogin`, `username`) | `[LOGIN_1]` |
| Паспорт, ИНН, СНИЛС, ПИНФЛ, ФИО — по имени поля; СНИЛС и по формату | `[DOC_1]`, `[NAME_1]` |
| IBAN (с проверкой контрольной суммы) | `[IBAN_1]` |
| Банковский счёт: 20 цифр с кодом валюты (`20208000…`, `40817810…`) или по полю | `[ACCOUNT_1]` |
| IP целиком (IPv4, IPv6, `::ffff:10.0.0.1`) и по полю (`clientIp`, `X-Forwarded-For`) | `[IP_1]` |
| Координаты: поля `lat/lon/latitude/longitude/geo/coords`, `userLatitude`, пары `41.311081, 69.279737` | `[GEO_1]` |
| Адрес и геоданные GeoIP: `address`, `street`, `city`, `city_name`, `postal_code` | `[ADDRESS_1]` |
| Многострочные `PRIVATE KEY` | `[PRIVATE_KEY]` |

**Одинаковое значение — одинаковая метка:** один и тот же email во всём логе будет `[EMAIL_1]`,
поэтому по замаскированному логу можно проследить путь клиента.

**Что специально НЕ трогается** (нужно для разбора инцидентов): даты и время, в том числе слитные
(`20260930183252-…` в `@MsgNum` — не карта), `order_id` и другие числовые ID, суммы, длительности,
trace/request UUID, порты, версии, имена классов, статусы (`loginResult: SUCCESS`).

## Настройка — файл `rules.toml`

- добавить своё поле: допишите имя в нужную группу секции `[keys]` (регистр и `_`/`-` не важны);
- поле, в имени которого есть слово (`OpLogin`, `receiverPhone`): секция `[keys_contains]` —
  имя делится на слова по регистру и `_`/`-`, поэтому `count` не заденет `account`;
- телефоны без `+` для других стран: секция `[phone]`, например `{ code = "7", digits = 10 }`;
- поля, где длинное число — норма (чтобы не было лишних `?`): `[suspects] ignore_keys`;
- координаты не скрывать, а огрублять до ~11 км: `geo_mode = "round"`;
- не маскировать служебные значения: секция `[allow]`;
- свой шаблон (номер договора и т.п.): секция `[[custom]]`;
- выключить правило: `[rules]`, например `uuid = true` чтобы маскировать и UUID.

Свой файл правил: `logmask --config my_rules.toml ...`

**Стабильные метки между запусками** (чтобы один клиент совпадал в логах за разные дни):

```
set LOGMASK_SALT=секретная-строка-команды
logmask --style hash service.log        → [EMAIL:3f9a1c02]
```

Соль храните как пароль — зная её, можно проверить, какой email стоит за меткой.

## Для CI / автоматизации

`logmask --check file.log` возвращает код `1`, если найдены данные, `0` — если чисто, `2` — ошибка.
Нераспознанные числа (`?`) на код выхода не влияют; с `--check --strict` — влияют.
В отчёте `--check` печатаются только уже замаскированные строки — оригинальные значения не выводятся.

## Важно

Маскирование по шаблонам не даёт 100% гарантии. Перед отправкой наружу бегло просмотрите результат,
особенно свободный текст (комментарии операторов, адреса, ФИО без имени поля).

Тесты: `python -m unittest discover -s tests`
